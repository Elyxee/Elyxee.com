# 加载优化 · 2026-10-08

## 范围

只调整首页素材交付与就绪时序。Home 的燃烧参数、开场点燃与退场时长、所有转场 shader、滚动与点击驱动、画框、Space / Dust / About 的人物与图片原件均保留。旧定档清单不覆盖，仍可对照 `90e97db` 和更早定档记录。

## 资源

- `Assets/optimized/home-fire.webp`、`home-ice.webp`、`combustion.webp` 为同尺寸无损导出。Pillow 及浏览器 Canvas 解码比较均确认 RGBA 像素完全一致。三张素材从 14,402,083 字节变为 10,726,814 字节。
- 六个社交图标按 256px 导出，原网页尺寸、材质、hover 与点击动画保持不变；原渲染画布只使用至约 68px 的图标位图。下载从 13,012,313 字节变为 511,502 字节。复制图标同样导出，不改变复制交互。
- Favicon 使用指定原图的 64px PNG（9,798 字节）；180px Apple 图标另外提供。原图 6,925,639 字节不再用作标签页图标。
- 同一燃烧素材的 384px 临时预览（138,038 字节）优先提供开场纹理；完整纹理随后替换，完整纹理就绪之后才开始原有退场动画。迟到的预览不会覆盖完整纹理。
- 首屏这批替换资源加预览，从 34,447,257 字节变为 11,464,934 字节，减少 66.7%。这不是整站所有场景的总大小。
- Portrait 人像下载优先级降低；隐藏且未挂载时不请求未使用的 Dust CSS 背景。Portrait 的挂载时机与场景切换不变。

原图保留在原目录；三张主纹理还作为 WebP 请求失败时的回退。详细文件尺寸与对应关系在 `loading-assets.json`。需要重新导出时，安装 Pillow 后运行 `python3 scripts/optimize-images.py`；主纹理的无损校验失败会终止脚本。

## 就绪接口与失败处理

`burn.ready` 在图片完成解码、上传并绘制首帧后完成；无 WebGL 时等静态背景解码完成。协调层 `waitForOpening` 同时等待首页、完整开场纹理、字体和文字材质，保留原 1.5 秒最短停留与 2.4 秒退场，不再把 7 秒超时当作素材已准备好。

开场期间的鼠标移动不积累隐藏的 Home 燃烧状态，滚动与触摸仍由原有加载输入门控处理。进入 Home 后原交互恢复。仅在主纹理及原图回退均失败时，开场保持遮挡并显示重试按钮；慢速但成功的请求不会触发错误界面。

## 验证

- 52 项行为测试通过，包含原有转场、画框、余烬测试和新增慢速就绪 / 解码 / 回退测试。
- 浏览器强制主纹理下载超过旧 7 秒时限：第 34.2 秒首页首帧完成，第 36.6 秒开场结束，未提前揭开半幅背景；开场纹理预览已正常显示。
- 人工令优化版 Ice 返回 503：自动请求原始 Ice，完整进入 Home。原图也失败时，保持开场并提供重试。
- 三张完整纹理浏览器解码结果与原 PNG 的每个 RGBA 像素相同；小图标只做适屏导出，未改变页面样式。

# 运行与加载优化 · 2026-10-10

## 范围

只清理浪费的绘制、同步等待和下载。所有 shader、动画参数、时长、输入手感、分辨率（dprCap）、图层与素材原图保持不变。

## 运行时

- **Home 光标（主要卡顿来源）**：烟雾的 `filter: blur()` 和火星的 `shadowBlur`，Chrome 会在与裁剪区域等大的临时图层里模糊——未裁剪时就是整张 2880×1800 画布，每颗粒子每帧一次。现在每颗粒子先裁剪到自身加模糊范围。逐像素对比：烟雾差异最多 1/255，火星约 0.06% 像素有亚像素差（最大 14/255），粒子本身每次都是随机的。`cursor-handoff.js` 的转场火星同样处理。
- **看不见时不画**：光标画布被隐藏（Portfolio、About、开场）或在冷态恢复中透明时，只继续模拟、不再绘制。Portfolio 在 Home 下方或 About 上方完全被遮住时，同样只推进状态和水波模拟，跳过全屏合成（`effect.setVisible`）。重新出现的第一帧状态与一直绘制时相同。
- **燃烧状态采样**：WebGL2 改为像素缓冲 + fence 异步读取，并去掉每次采样后的 `getError()`。Chrome 读取时仍有一次 GPU 进程往返，但每次阻塞从约 90–100 ms 降到约 20 ms；采样间隔和判定逻辑不变。WebGL1 保留原同步读取。
- **About 预备**：原来在 Home → Portfolio 转场中途创建 About 图层和两个 WebGL 上下文；现在等 Portfolio 到达后空闲时再做。2026-10-11 起 About 与舞台共用同一条火线，不再有第二个火线画布（见 [interfaces.md](interfaces.md)）。
- **第一次切到 Dust 的卡顿**（2026-10-11）：Dust 的画框贴图原来要等切换那一刻才在动画帧里当场制作，需要同步解码几张大图并读回像素，第一次切换常掉到 12–26 fps、拖到 4–6 秒。现在 Portfolio 装载后，画廊在空闲时逐张准备另一场景的贴图，图片先在后台线程解码，制作仍走原来的 `textureFor()`，结果相同；切换稳定约 2.7 秒、55–60 fps，Home 上没有新增卡顿。
- 删除无人使用的代码：Burn 每帧测量标题和图标位置并写入四个 CSS 变量（无样式读取）、`data-burn-scene`、`is-recovering`；光标测试页残留的 `#motion-state` / `#test-button` / `body[data-motion]`；`data-figma-node`。

## 加载

- Portfolio 中所有使用路径都逐像素一致的十张图改为无损 WebP，放在 `Assets/optimized/` 下并镜像原路径：Space、Dust、UFO、四张不透明封面，以及不嵌封面的三个画框。Chrome 中 2D Canvas 与 WebGL 两条解码路径都已逐像素核对。
- 保留 PNG：两张人像（参与光环线条生成，经 2D Canvas 后会有像素差）、六个嵌封面的画框和 About 主图。Chrome 对 PNG / WebP 半透明边缘的预乘取整不同，最多 1/255，但为保证完全一致不替换。另有五个实为 JPEG 数据的 `.png` 原样保留。
- 2026-10-17 起 Portfolio 全部图片改为有损 WebP，本节的逐像素一致与保留 PNG 已被取代，见下一节。
- Portfolio 静态回退里的两张人像（2.4 MB）改为在 Portfolio 挂载时才请求，不再和开场素材抢带宽。

# Portfolio 加载体验 · 2026-10-17

- 线上实测（未限速）：进入 Home 6.7 秒，Portfolio 完全准备好 20.3 秒。Portfolio 约 31 MB，进入 Home 后要再等十几秒；这段时间进入 Portfolio 会看到下载中的图片。
- Home 自己的图片和火线纹理一到，开场剩下的时间就开始在后台下载 Portfolio（先 Space，后 Dust），只下载不绘制，开场时间不变。17 Mbps 下 Portfolio 准备好从 23.6 秒提前到 20.6 秒，总下载量不变（43 MB），后台下载被直接复用。
- 加载期间的静态构图不再显示下载到一半的图片：背景、人像、画框各自完整到达后淡入（0.6 秒）；动态画面准备好后以 0.6 秒淡入接替。
- 切换场景后，Elyxee 链接与切换按钮一起以 0.8 秒淡入（原来链接直接出现、按钮 0.4 秒）。
- 本地预览改用 `node scripts/serve.mjs`，与线上一样支持直接打开 `/portfolio`、`/about`。
- **有损压缩（经确认改变像素）**：Portfolio 的 20 张图（Space、Dust、两张人像、UFO、九个画框、六张封面）改为 WebP 质量 90，透明通道保持逐像素一致，边缘轮廓不变。约 31 MB → 6.2 MB（Portal 本就是 JPEG 数据，原样保留）。与原图的 PSNR 为 32.4–44.9 dB；Dust 最低，是满屏细颗粒在有损 WebP 色度减半后的固有结果，提高质量也不会上升，100% 与放大对比均看不出差异。Home 与 About 的图片未改。`optimize-images.py` 对每张校验尺寸、透明通道和 30 dB 下限。
- 17 Mbps 模拟网络：进入 Home 8.2 秒（不变），Portfolio 准备好从 23.7 秒（本轮之前）提前到 9.4 秒，整站下载 43 MB → 18 MB。


# 流畅度 · 2026-10-18

## 开场结束时

- 开场揭开 Home 的过程中点导航，原来会被丢掉；现在记下，开场一结束就执行。悬停预加载 About 也推迟到开场结束，避免卡住退场的火。
- 火焰光标原来要等开场结束后鼠标再动一下才出现；现在开场结束那一帧就在鼠标所在位置点亮（鼠标在窗口内且窗口有焦点时）。
- 开场结束后后台装配 Portfolio，原来一次性做完，主线程连续卡 0.25 s 和 0.39 s，光标冻住、点击无响应。现在：大图先在后台线程解码；每张大图上传 GPU、光环、星点、每个封面合成之间都让出一帧；首帧需要的画廊贴图每帧只做一张。产出完全相同，只是分散了。最长一帧从约 390 ms 降到约 85 ms。

## 转场（滚轮、按键、点击）

- Home 的燃烧状态每 0.45 s 从 GPU 读回一次。转场时 GPU 满载，这次读回要排在整帧绘制之后，每次卡 20–60 ms。现在开场和转场期间暂缓读回，结束后立即补一次（`burn.holdSamples`，经 Home 场景的 `setPassing`）。
- 拉远景深（SVG 位移滤镜）的开销与滤镜区域面积成正比，原来三块全屏区域（燃烧层、文字层、Portfolio 层）。现在燃烧层只算火线以上、Portfolio 只算火线以下、三块文字各自只算所在区域，各加上最大位移量的余量。区域起点对齐位移图的网格，测试页逐像素对比与全屏区域完全一致（1024×768 与 1440×900，各位移强度）。
- Portfolio 的 WebGL 画面淡入完成后，下面被完全盖住的静态构图隐藏；Home 的 WebGL 就绪后，被盖住的底图去掉。画面不变，转场时不再反复解码和合成看不见的图片。
- 1440×900、120 Hz 实测：转场约 62 fps（p95 25 ms，最长 40–60 ms）→ 点击约 81 fps、滚轮约 96 fps（p95 17 ms，最长约 18–33 ms）。

## 进站后的火焰光标 · 2026-10-18

- 进站后移动鼠标仍会顿：开场后 Portfolio 的一次性准备（大图上传 GPU、星点与光环、封面合成、画廊贴图，共约 0.9 s 主线程工作，每块 60–80 ms）正好落在访客刚开始移动火焰的时候。光标本身每帧不到 1 ms，不是它的问题。
- 现在这些准备只在鼠标静止 0.3 s 以上时一块一块地做；访客指向 Portfolio 链接、滚动或点击前往时立刻做；最多等 6 s。产出不变，只是换了时机（`mountPortrait` 的 `canWork`）。
- 实测：进站后连续移动 3 s，期间没有任何卡顿（无长任务、无超过 30 ms 的帧）；停下后约 1.1 s 内准备完毕。一直不停地移动的话，第 6 s 开始准备，约 0.7 s 内有几次轻微顿挫。
