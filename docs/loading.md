# 加载优化 · 2026-10-08

## 范围

只调整首页素材交付与就绪时序。Home 的燃烧参数、开场点燃与退场时长、所有转场 shader、滚动与点击驱动、画框、Space / Dust / About 的人物与图片原件均保留。旧定档清单不覆盖，仍可对照 `90e97db` 和更早定档记录。

## 资源

- `Assets/optimized/home-fire.webp`、`home-ice.webp`、`combustion.webp` 为同尺寸无损导出。Pillow 及浏览器 Canvas 解码比较均确认 RGBA 像素完全一致。三张素材从 14,402,083 字节变为 10,726,814 字节。
- 六个社交图标按 256px 导出，原网页尺寸、材质、hover 与点击动画保持不变；原渲染画布只使用至约 68px 的图标位图。下载从 13,012,313 字节变为 511,502 字节。复制图标同样导出，不改变复制交互。
- Favicon 使用指定原图的 64px PNG（9,798 字节）；180px Apple 图标另外提供。原图 6,925,639 字节不再用作标签页图标。
- 同一燃烧素材的 384px 临时预览（138,038 字节）优先提供开场纹理；完整纹理随后替换，完整纹理就绪之后才开始原有退场动画。迟到的预览不会覆盖完整纹理。
- 首屏这批替换资源加预览，从 34,447,257 字节变为 11,464,934 字节，减少 66.7%。这不是整站所有场景的总大小。
- Portrait 人像下载优先级降低；隐藏且未挂载时不请求未使用的 Dust CSS 背景。Portrait 的挂载时机与场景切换不变。

原图保留在原目录；三张主纹理还作为 WebP 请求失败时的回退。详细文件尺寸与对应关系在 `loading-assets.json`。需要重新导出时，安装 Pillow 后运行 `python3 scripts/optimize-images.py`；主纹理的无损校验失败会终止脚本。

## 就绪接口与失败处理

`burn.ready` 在图片完成解码、上传并绘制首帧后完成；无 WebGL 时等静态背景解码完成。协调层 `waitForOpening` 同时等待首页、完整开场纹理、字体和文字材质，保留原 1.5 秒最短停留与 2.4 秒退场，不再把 7 秒超时当作素材已准备好。

开场期间的鼠标移动不积累隐藏的 Home 燃烧状态，滚动与触摸仍由原有加载输入门控处理。进入 Home 后原交互恢复。仅在主纹理及原图回退均失败时，开场保持遮挡并显示重试按钮；慢速但成功的请求不会触发错误界面。

## 验证

- 52 项行为测试通过，包含原有转场、画框、余烬测试和新增慢速就绪 / 解码 / 回退测试。
- 浏览器强制主纹理下载超过旧 7 秒时限：第 34.2 秒首页首帧完成，第 36.6 秒开场结束，未提前揭开半幅背景；开场纹理预览已正常显示。
- 人工令优化版 Ice 返回 503：自动请求原始 Ice，完整进入 Home。原图也失败时，保持开场并提供重试。
- 三张完整纹理浏览器解码结果与原 PNG 的每个 RGBA 像素相同；小图标只做适屏导出，未改变页面样式。
